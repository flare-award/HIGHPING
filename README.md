# Latency Studio

**Latency Studio** — Windows-приложение для реального добавления задержки к внешнему IP-трафику компьютера. Оно использует официальный WinDivert на сетевом уровне: перехватывает пакеты, удерживает их в ограниченной очереди и повторно отправляет по таймеру. Это не визуальная подмена показаний и не настройка сокета одной выбранной игры.

> Искусственная задержка ухудшает игровой процесс, голосовую связь, видеозвонки, загрузки и работу приложений, чувствительных к тайм-аутам. Совместимость с античитами CS2, VALORANT и других игр **не проверена и не гарантируется**. Используйте программу только на своём компьютере и не применяйте её для обхода защит или правил сетевых сервисов.

## Возможности

- Перехват внешнего IPv4/IPv6-трафика на компьютере для разных приложений одновременно.
- Фиксированный режим TCP/UDP с отдельными исходящей и входящей задержками.
- Целевой RTT с честной калибровкой по новым TCP handshake; неизвестный RTT не заменяется выдуманной статистикой.
- Реальный TCP connect тестового узла, три раздельные метрики, счётчики пакетов, глубина очереди и ошибки.
- Тёмный WPF-интерфейс, разделы «Настройки», «Диагностика», «О программе», системный трей и опциональный автозапуск.
- Ограниченная очередь до 8 192 пакетов / 64 МиБ. При переполнении обработчик отправляет ожидающие пакеты соответствующего направления и новый пакет без дополнительного ожидания, вместо намеренной потери.
- UAC запрашивается только при включении системного перехвата, если приложение запущено без прав администратора.
- Настройки хранятся в `%LOCALAPPDATA%\LatencyStudio\settings.json`; журнал — в `%LOCALAPPDATA%\LatencyStudio\logs\app.log`.

## Системные требования

- Windows 10 x64 или Windows 11 x64. Для Windows 10 рекомендуется актуальная обслуживаемая версия.
- Права администратора **только для включения перехвата**. Пользовательский интерфейс запускается обычным процессом; Windows показывает штатный UAC перед загрузкой WinDivert.
- В установщике/ZIP поставляются самодостаточная сборка .NET 10, `WinDivert.dll` и подписанный `WinDivert64.sys`. Отдельно устанавливать .NET не нужно.
- Нужен доступ к выбранному тестовому TCP-узлу, если требуется измерить TCP connect RTT.

## Установка и первый запуск

1. Скачайте установщик или ZIP из GitHub Actions Artifacts (или GitHub Releases после публикации тега).
2. Для установщика запустите `LatencyStudio-Setup-1.0.0-x64.exe` и завершите мастер. Для portable-версии распакуйте весь архив в отдельную папку и запускайте `LatencyStudio.exe` из неё; не удаляйте DLL/драйвер и папку `ThirdPartyNotices`.
3. Запустите программу. По умолчанию задержка выключена.
4. Выберите «Целевой RTT» либо «Фиксированная задержка», при необходимости задайте тестовый узел и исключения портов.
5. Нажмите **Измерить RTT**, чтобы получить реальное TCP connect измерение выбранного узла.
6. Нажмите **Включить задержку**. Если приложение запущено без администратора, подтвердите запрос UAC Windows. WinDivert нужен для системного перехвата и повторной отправки пакетов.
7. Статус «АКТИВНО» означает, что WinDivert handle открыт. Нажмите **Выключить задержку** или выберите эту команду из меню трея, чтобы остановить новый перехват, дочитать уже накопленную очередь драйвера, передать пакеты без ожидания и немедленно освободить user-mode очередь.

## Два режима

### Целевой RTT

По умолчанию цель — **95 мс**. Для нового TCP-соединения приложение измеряет исходящий SYN → входящий SYN-ACK и, если оценка пригодна, вычисляет остаток `max(0, целевой RTT − исходный RTT)`. Остаток делится поровну между направлениями. Например, при исходной оценке 20 мс планируется ориентировочно 37,5 мс в каждом направлении.

Ключевые ограничения:

- Калибровка — handshake конкретного TCP-потока, а не игровая телеметрия или RTT каждого приложения.
- Пока для потока нет пригодного handshake, искусственная задержка этого потока **не добавляется**.
- Уже существующие на момент включения TCP-соединения, UDP/QUIC и ICMP не имеют универсального источника RTT и в целевом режиме не задерживаются. Для таких приложений используйте фиксированный режим.
- Если исходная задержка выше целевой, программа не может уменьшить её и добавляет 0 мс.

### Фиксированная задержка

По умолчанию — **40 мс исходящего** и **40 мс входящего** трафика. Для симметричного обмена это добавляет приблизительно 80 мс к RTT. Задержка применяется к перехваченным внешним TCP/UDP и другим IP-пакетам, в том числе IPv4/IPv6; маршрут, обработка сервером, повторные передачи и способ измерения влияют на итог.

Настройки действуют на весь IP-трафик компьютера, а не на один выбранный процесс. В исключения можно добавить до 64 портов TCP/UDP, например `53, 123`. Loopback и уже внедрённые impostor-пакеты исключаются всегда. Исключение процесса по имени/PID не предусмотрено: выбранный WinDivert NETWORK layer не сообщает процесс-владелец пакета.

## Как читать показатели

В интерфейсе значения намеренно разделены:

1. **Исходная измеренная задержка** — baseline тестового узла или отдельного TCP-flow, полученный по handshake. Если данных нет, показывается `—`.
2. **Добавленная задержка** — расчёт конфигурации: фиксированная сумма исходящего и входящего значений либо остаток целевого RTT для известного baseline. Это план добавки, а не обещание итогового пинга.
3. **Фактический RTT тестового соединения** — измеренное время TCP connect к заданному `host:port`, без TLS/HTTP. При активной задержке измерение её включает. Это не универсальный ping CS2/VALORANT/Discord или любого другого сервера.

Кнопка измерения создаёт настоящее кратковременное TCP-соединение. Сетевое соединение может быть заблокировано firewall/провайдером или выбранным узлом.

## Фоновый режим и автозапуск

- По умолчанию крестик окна скрывает программу в системный трей. Это можно выключить на странице «Настройки».
- Меню трея открывает окно, переключает задержку или полностью завершает Latency Studio. Завершение останавливает приём, немедленно отправляет пакеты в очереди и закрывает WinDivert handle.
- «Запускать вместе с Windows» выключен по умолчанию. При запуске из трея задержка остаётся выключенной; автоматического сетевого воздействия без явного включения нет.

## Безопасность и известные ограничения

- В поставке используется официальный **WinDivert 2.2.2 A x64** с подписанным драйвером. Установщик не отключает защиту Windows, антивирус или проверку подписи. При блокировке драйвера приложение остановит обработчик и покажет ошибку.
- Пакеты не изменяются по содержимому и не теряются намеренно. Loopback не перехватывается. Портовые исключения можно менять без перезапуска.
- При обычном выключении очередь освобождается немедленно. При принудительном убийстве процесса или аварии часть уже удерживаемых в пользовательской очереди пакетов может потеряться; нулевой риск при аварийном завершении гарантировать нельзя.
- WinDivert NETWORK layer действует системно, но не сообщает PID и не позволяет надёжно исключать приложения по имени процесса.
- Целевой режим ограничен TCP handshake. UDP-игры/QUIC требуют фиксированного режима, если нужна именно искусственная задержка.
- Сильная нагрузка, планировщик Windows, маршруты, QoS, сетевой адаптер, firewall и драйверы могут добавить джиттер или повлиять на пропускную способность.
- Не проверялась совместимость с античитами конкретных игр. Не гарантируется, что античит разрешит наличие WinDivert или перехват трафика.
- Программа не может заставить игровой сервер измерять RTT тем же способом, что и TCP-тестовый узел. Не обещается итоговое число пинга во всех приложениях.

## Диагностика

1. Проверьте на странице «Диагностика», что найдены `WinDivert.dll` и `WinDivert64.sys`.
2. Если появляется сообщение об отказе в доступе, повторно нажмите включение и подтвердите UAC. Если UAC отменён, задержка не включается.
3. При коде ошибки Windows 577/1275 проверьте журнал безопасности/защиту Windows и целостность пакета. Не отключайте защитные механизмы; скачайте официальный артефакт заново.
4. Если тестовый RTT недоступен, проверьте адрес, порт и доступность узла. Можно указать `example.org:443` или свой TCP-узел.
5. Используйте кнопку **Скопировать отчёт** или откройте журнал из раздела «Диагностика». Отчёт содержит состояние приложения и счётчики, но не дамп сетевых пакетов.
6. При занятом/несовместимом драйвере проверьте, не использует ли WinDivert другое ПО. Не запускайте одновременно несколько packet-divert инструментов без необходимости.

## Полное удаление

- Удалите Latency Studio через **Параметры Windows → Приложения** или ярлык деинсталлятора.
- Деинсталлятор удаляет установленные файлы, свой HKCU автозапуск и `%LOCALAPPDATA%\LatencyStudio` (настройки и журнал).
- В штатном завершении приложение закрывает WinDivert handle, останавливает приём и освобождает очередь. WinDivert загружает драйвер по требованию; Latency Studio не оставляет собственную постоянную службу для задержки.
- Для portable-версии завершите программу и удалите распакованную папку. Если вы отдельно включили автозапуск в настройках, выключите его до удаления portable-папки.

## Сборка разработчиком

Требуются Visual Studio 2022 / .NET 10 SDK и Windows x64 для WPF-сборки. Для установки Inno Setup 6 нужен `ISCC.exe`; workflow устанавливает его через Chocolatey, если он отсутствует.

```powershell
dotnet restore HighPing.sln
dotnet test HighPing.sln -c Release

dotnet publish src/LatencyStudio.App/LatencyStudio.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishReadyToRun=true -o artifacts/publish/win-x64

./scripts/Download-WinDivert.ps1 -Destination artifacts/publish/win-x64
Copy-Item -LiteralPath README.md -Destination artifacts/publish/win-x64 -Force
Copy-Item -LiteralPath LICENSE -Destination artifacts/publish/win-x64 -Force
Copy-Item -LiteralPath THIRD-PARTY-NOTICES.md -Destination artifacts/publish/win-x64 -Force
```

Для установщика выполните Inno Setup Compiler по `installer/LatencyStudio.iss`, передав `/DPublishDir=<полная папка публикации>` и `/DOutputDir=<папка артефактов>`. GitHub Actions воспроизводит эти шаги для каждого изменения, а для тега `v*` добавляет файлы в GitHub Release.

## Тесты и текущий статус проверки

Автоматические тесты покрывают валидацию значений, расчёт целевого/фиксированного RTT, проверку TCP-пакетов и handshake baseline, дедлайны/порядок/сброс/переполнение очереди, жизненный цикл и ошибки backend-контроллера, сохранение и восстановление JSON-настроек.

Тесты Core не требуют драйвера и не доказывают фактическую совместимость WinDivert с каждой сетевой картой/античитом. Реальная загрузка драйвера и измерение RTT должны проверяться на Windows 10/11 с разрешённым UAC. Текущий статус окружения разработки приведён в [docs/VERIFICATION.md](docs/VERIFICATION.md).
